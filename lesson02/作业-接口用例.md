# 第 2 课作业 · 接口用例

> 对象：你自己的 bluemoon 项目。先把两个接口的**真实路由和字段**填到下面，再设计用例。
> 交付目标：合计 ≥ 15 条，覆盖参数/鉴权/业务规则/安全四类。

## 0. 被测接口登记（先填这个）

| 代号 | 方法 + 路径 | 用途 | 鉴权要求 | 关键字段（从 /docs 或 pydantic 模型抄） |
|---|---|---|---|---|
| A | ❓ 待填，如 `POST /api/auth/login` | 登录 | 否 | 待填 |
| B | ❓ 待填，如 `POST /api/articles` | 发文章 | 是 | 待填 |

## 1. 用例表（模板，照抄扩展）

| 编号 | 目的 | 请求（方法+路径+头+体） | 前置数据 | 预期（状态码+body+DB） | 依据 |
|---|---|---|---|---|---|
| API01 | 正常登录（基线） | `POST /api/auth/login`，body `{"username":"13800138000","password":"Abc123"}` | 用户已注册 | 200；data.token 非空；last_login 更新；不回显明文密码 | 基线 |
| API02 | 密码错误 | 同上，password 改错 | 用户已注册 | 401 或 200+业务失败码（按你项目实际规范写死一种）；msg 不区分账号/密码错 | 无效类 |
| API03 | 账号字段缺失 | body 不带 username | — | 422；detail 指出字段缺失；不产生登录记录 | 必填 |
| API04 | 类型混淆：password 传数字 | `{"username":"...","password":123456}` | 用户已注册 | 422；不 500 | 类型 |
| API05 | 超长密码 10000 字 | password = "a"×10000 | 用户已注册 | 422/400 有明确上限提示；服务不超时、不崩 | 边界/安全 |
| API06 | SQL 注入用户名 | `{"username":"' or 1=1 --","password":"x"}` | — | 401；响应不含 SQL 片段/堆栈 | 安全 |
| API07 | 水平越权：A 用户 token 改 B 用户文章 | `PATCH /api/articles/{B的id}`，带 A 的 token | A、B 各一篇文章 | 403 或 404；B 的文章未被改动（查 DB 确认） | 鉴权 |
| API08 | 垂直越权：普通用户调 admin 接口 | 普通 token 请求 admin 路由 | 普通用户已登录 | 403；不返回任何业务数据 | 鉴权 |
| API09 | 无 token 访问受保护接口 | 不带 Authorization 头 | — | 401 | 鉴权 |
| API10 | 草稿不可见（业务规则） | 用他人身份 GET 草稿文章 | 存在他人草稿 | 404/403；列表接口也不出现该草稿 | 业务规则 |

## 2. 自查清单（交作业前逐条打勾）

- [ ] 两个接口的路由、字段是从项目里**真实抄来的**，不是猜的
- [ ] 合计 ≥ 15 条，A ≥ 7、B ≥ 8
- [ ] 参数类 ≥ 6：包含 2 条边界（字符串长度/分页）、2 条类型混淆
- [ ] 鉴权类 ≥ 4：水平越权、垂直越权各 ≥ 1
- [ ] 业务规则 ≥ 2：来自项目真实规则
- [ ] 安全类 ≥ 2：SQLi / XSS / 超长
- [ ] 每条都写了「依据」，能回答「为什么存在」
- [ ] 预期结果写清了状态码，而不是只写「成功/失败」
