# 第 2 课 · 接口测试设计

> 一句话：**UI 用例测「用户看到的」，接口用例测「系统承诺的」。前端校验永远不算数。**

## 一、今天要拿下的三件事

1. 能把一个 UI 用例「翻译」成接口用例（思维迁移，不是新知识）
2. 记住每条接口用例的「五项检查」
3. 针对你自己的 bluemoon 项目，产出 15 条真实接口用例

## 二、为什么接口测试是测开的主战场

- **面试**：测开岗的用例设计题，80% 是「给这个 API 设计用例」
- **效率**：UI 用例分钟级、靠人点；接口用例秒级、能进 CI
- **本质**：前端校验是给用户看的体验，后端校验是给安全看的底线。**绕过前端直打接口**，才是测试该干的活

一句话记住：**前端限制 ≠ 后端限制。** 前端 `maxlength=20` 只是键盘上的礼貌，后端到底拦不拦，只有接口知道。

## 三、同一个登录，两种写法

| 维度 | UI 用例（TC01） | 接口用例（API01） |
|---|---|---|
| 操作面 | 输入框 + 点按钮 | `POST /api/auth/login` + JSON body |
| 观察面 | 界面提示、页面跳转 | 状态码 + 响应体 + 数据库 + 副作用 |
| 能否绕开前端校验 | 不能（被前端拦） | 能——直接构造报文 |
| 执行成本 | 分钟级 | 秒级，可自动化 |

接口用例的「预期结果」永远要回答四个问题：

1. 状态码是多少？
2. 响应体长什么样（业务 code / msg / data）？
3. 数据库变了吗？
4. 有没有副作用（重复提交、并发、缓存、通知）？

## 四、五项检查（每条接口用例的骨架）

| # | 检查项 | 要验什么 |
|---|---|---|
| ① | **状态码** | 语义正确：200 / 400 / 401 / 403 / 404 / 422 / 500 各归各位。参数校验失败用 422 或 400 都行，但**全项目要一致**，不能一会儿 200+code=1 一会儿 400 |
| ② | **响应体** | 字段齐全、类型正确；错误信息**不泄漏**堆栈、SQL、内部路径、服务器版本 |
| ③ | **数据契约** | 必填/选填、多余字段（Pydantic `extra` 是 ignore 还是 forbid）、`null` vs 字段缺失、类型严格（数字 `1` 和字符串 `"1"` 不是一回事） |
| ④ | **数据落库** | 该写的写了吗（成功注册 → users 表 +1 行）；不该写的没写吗（失败的请求不产生脏数据） |
| ⑤ | **副作用与幂等** | 同一请求连发两次会怎样（重复注册？重复发帖？）；并发同时来会不会覆盖/超卖 |

> 面试答「接口用例怎么设计」，把这五项背出来，比背 20 条零散用例值钱。

## 五、参数四板斧（等价类搬家）

| 板斧 | 接口版演绎 | 例子 |
|---|---|---|
| 必填/缺失 | 少字段、多字段、`null`、空串 | `{"username": null}`、body 里不带 `password` |
| 类型混淆 | 数字传字符串、数组传对象、布尔传 `"false"` | `{"age": "18"}`、`{"tags": {"a": 1}}` |
| 边界值 | 字符串长度、数值范围、分页参数 | `page=0 / -1 / 100000`、`size=0`、标题 1 字/200 字/201 字 |
| 恶意输入 | SQLi、XSS、超长、emoji、控制字符、深嵌套 | `{"title": "a" × 100000}`、`{"name": "<img onerror=alert(1)>"}` |

**金矿提醒**：接口层的长度限制通常比前端松。前端限制 maxlength=20，后端可能到 200 才拦——每一条「前端挡住了」的输入，都值得在接口层再试一次。

## 六、鉴权矩阵（越权六连）

针对需要登录的接口，把「身份」当参数测：

1. 不带 token → 401
2. 伪造 token（改一个字符 / 过期 / 空串）→ 401
3. 用别人的 token 访问我的资源（**水平越权**）→ 403 或 404（404 更好，不泄漏资源存在性）
4. 普通用户 token 调 admin 接口（**垂直越权**）→ 403
5. token 放错位置（该放 Header 却放 query / cookie）→ 401
6. 登出后旧 token 还能用吗 → 401（验证失效机制）

> 你的 bluemoon-autotest 里已经写过越权用例——今天要做的是把它**体系化成矩阵**，而不是零散几条。
